# Consolidated 0.2.9.dev0 evaluation candidate

This prepares fresh **unpublished development archives**, not final v0.2.9 assets.
Public [v0.2.8](https://github.com/YuzeJ21/Scope-Proof/releases/tag/v0.2.8) remains the
evaluation download. The earlier private candidate and maintained examples remain unchanged.

The new candidate consolidates CLI CI snapshots, CI follow-up, the maintained no-install
walkthrough, same-commit CLI/workbench comparisons, guarded downloads and inline run outcomes.
It changes no evidence level, deterministic gate, saved-record format or historical producer
identity. Source and installed checks are constructed engineering evidence; independent-use
and qualifying-review counts remain zero.

## Where to obtain a candidate

After a successful **main CI** run, open its Actions summary and download
`scopeproof-evaluation-candidate-COMMIT-ATTEMPT`. The enclosing PR records the verified main
commit, exact run and artifact link. CI artifacts have 90-day retention; they are not GitHub
Release assets or a permanent public-download promise.

A pull-request run also checks preparation, but its manifest has `source_kind: pr-merge`
and its actual synthetic merge SHA/tree. It is a preview, not the separately rebuilt main
candidate. Always inspect `candidate.json`: require `source_kind: main`, the intended full
commit/tree, the exact run attempt and successful corresponding CI before evaluating distribution.

Each packet contains:

| File | Purpose |
| --- | --- |
| `scopeproof-0.2.9.dev0-py3-none-any.whl` | Actual wheel used by the installed CLI checks. |
| `scopeproof-0.2.9.dev0.tar.gz` | Source archive rebuilt to a byte-identical wheel. |
| `SHA256SUMS.txt` | Exact archive byte digests. |
| `candidate.json` | Strict validated source, archive, test, wheel and installation bindings. |
| `README.md` | Candidate identity, consumption instructions and limits. |

Verify both archive digests against `SHA256SUMS.txt` before installation. In a new virtual
environment, install the wheel using `python -m pip install ./scopeproof-0.2.9.dev0-py3-none-any.whl`.
The [evaluation guide](../evaluation-guide.md) explains the workbench, saved-review folders and
constructed CI manifests. Development archives must not be renamed to look like a final release.

## What the preparation verifies

The existing CI job builds the wheel and source archive, rebuilds the source archive and
requires exact wheel equality. It installs that candidate wheel for the existing CLI checks.
Every numbered browser-fixture build must provide exactly one matching wheel. All wheel
Python entries must match the intended package inventory; all source-archive Python entries,
including scripts and tests, must match the tracked checkout under its declared exclusions.
The checkout must match the trusted workflow event SHA. Source/browser pytest XML totals and
individual case outcomes must agree and contain no failures, errors or unsupported nesting.

A separate source-wheel installation imports the core and workbench from its own environment,
checks installed version/core identity and runs both existing constructed benchmarks. Its
runtime dependencies are inherited from the tested CI environment; this is package isolation,
not a second clean dependency resolution. The browser journeys use their existing fresh
environments. Python/Windows compatibility jobs remain separate source/package observations;
they do not claim that every platform installed these exact retained Linux wheel bytes.
Raw run-outcome values are asserted through AppTest. The installed journey checks the
comparison flow and the run-context view's availability; it does not inspect canvas cell text.

The workflow supplies an output path outside the checkout and actual boolean probe flags.
Two helper-interface refinements remain deferred: rejecting an in-checkout output path and
requiring literal booleans for true-only probe flags and nonblank environment labels. These do not
change the concrete CI invocation or its generated probe values.

Hatch's [reproducible build configuration](https://hatch.pypa.io/latest/config/build/#reproducible-builds)
supports a fixed `SOURCE_DATE_EPOCH`. The engineering job uses its stable default epoch for
all relevant builds and still checks actual byte equality. The schema, checksums and CI URL
are inspectable bindings, not signed provenance or authentication of arbitrary uploaded data.

No packet is retained when preparation fails. Successful packet creation is followed by the
workflow's aggregate verification; inspect that final run result as well as the artifact.
