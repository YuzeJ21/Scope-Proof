## Historical release blockers at the pre-repair public main

The following findings describe the pre-repair public `main` audit. The
public-main alignment at the top of this document records their verified
resolution merged by PR #177. The published release remains unchanged.

### Core lifecycle can produce False Ready

`append_resolution()` accepts a final-acceptance event without enforcing
`can_record_final_acceptance()`. In a confirmed, completely ingested review
with passing observed CI and one unresolved `SHOULD_HAVE` criterion:

- `can_record_final_acceptance()` returned `False`;
- appending `final_acceptance=True` produced `Ready` with zero criterion
  resolutions; and
- `validated_review_state()` accepted the result as schema-valid and
  deterministically self-consistent.

The same core entry point also accepted a `MANUALLY_VERIFIED` decision without
the atomic `append_external_verification()` path. A subsequent final event
produced a schema-valid `Ready` review with zero `RuntimeEvidence` records.
The then-current workbench guarded the intended UI path, but the exported core
lifecycle did not enforce the rule.

The merged product tree rejects ineligible final events and unpaired
manual-verification events. Red-green regressions prove that persisted and
exported states cannot bypass either boundary.

### Candidate retrieval can lose exact-head anchoring

`fetch_candidate_files()` interpolates a validated-but-unencoded repository
path into a URL before adding `?ref=<head_sha>`. A candidate path of
`src/probe.py?mode=default` generated:

```text
/contents/src/probe.py?mode=default?ref=<head_sha>
```

The HTTP client parsed no `ref` parameter, but the returned `RetrievedFile`
still recorded the supplied head SHA. This can misstate immutable provenance
for explicitly requested unchanged candidates.

The merged product tree encodes path segments, supplies `ref` separately,
validates the SHA at the retrieval boundary, and has regressions for `?`, `#`,
`%`, Unicode, and the actual transmitted `ref`.

### Resolved follow-up hardening

The repair merged by PR #177 also:

- restricts same-head Action updates to GitHub Actions bot-authored comments;
- makes the repository Action use the checked-in frozen environment; and
- scopes Pages write and OIDC permissions to deployment.
