# Explicit multi-criterion JUnit mapping before import

The owner delegates task selection, design, automated verification/review and guarded merge, and declines personal testing and qualifying reviews. Main9862293/PR240 is clean and green. Two independent gap reviews found a concrete limitation: the workbench maps every selected JUnit scope only to the inspected criterion, while the immutable artifact digest cannot be imported again. One report spanning two criteria therefore cannot be correctly imported through that form.

## Chosen approach

The implementer chooses a session-only mapping draft before one existing import. Alternatives were persisted correction/withdrawal events (larger lifecycle/migration/reporting scope), and richer resolution-audit exports (useful but a reporting rather than import outcome). Neither is included. Existing saved imports remain immutable, with duplicate-artifact and no-case-to-multiple-criteria rules unchanged.

A pure core helper module `scopeproof_core/importers/junit_draft.py` owns frozen extra-forbid Pydantic `JUnitMappingDraft(state_fingerprint, artifact_sha256, selections)` with at most5,000 canonical unique scope/criterion pairs, matching the existing mapping-document selector limit. No raw XML, importer or timestamps are persisted in the draft. Its full validated review fingerprint and computed artifact digest must match before staging, removal or final build. New drafts require confirmed active criteria/provenance and an exact40-character head. Existing parser/builder/lifecycle validate every addition/final candidate, including explicit overlap, unknown scopes/criteria, duplicate imported artifact and existing parser limits. Neither matching digests nor drafts establish authenticity/runtime truth.

Interfaces: `new_junit_mapping_draft(state, artifact_bytes)`, `extend_junit_mapping_draft(state, artifact_bytes, draft, selections, *, importer)`, `remove_junit_mapping_criterion(state, artifact_bytes, draft, criterion_id)`, and `build_drafted_junit_import(state, artifact_bytes, draft, *, importer, limitations=None)`. Additions are transactional: rejected choices leave the old draft untouched. Same-criterion suite/case overlap remains the existing canonical union; cross-criterion overlap is rejected. Removing a criterion group removes only its staged pairs; clearing all does not modify saved imports.

`apps/web/junit_mapping.py` renders an independent **JUnit mapping target criterion** selector (initially unselected), existing **Map JUnit scopes to the selected criterion** multiselect, **Add selected scopes to mapping draft**, canonical staged preview, **Remove criterion mapping from draft** and **Clear staged JUnit mappings**. It returns a validated candidate only for an explicit nonempty staged draft with no unsubmitted target/scope choice. The existing final Save button appends once through the unchanged lifecycle. Stage/reset notices distinguish draft edits from a recorded import. Sources/names/IDs render as inert text/code.

Artifact change, malformed/removed upload, full review/criteria/head/provenance change and existing global form reset clear dependent draft controls before rendering. Importer/limitations can be edited before final save. The existing inspected-criterion change clears criterion-detail drafts; use the independent mapping-target selector to map multiple criteria without changing the inspected criterion. Pending-input/export/reopen guards include the new draft. The raw byte limit1MiB, suites100/cases5,000/elements20,000, import limit, source exclusions, saved v7, gate/evidence/runtime/decision truth and frozen R-002 remain unchanged. No new parser, adapter family, migration, source execution, network fetch or persisted event type.
