# Inspect loaded changes before a file-scope decision

The owner delegated selection and execution of the next useful Stage 2 outcome and declined routine design input, personal testing and qualifying reviews. Independent gap reviews found that the scope form shows names and prior decisions but no source context. This bounded change makes already-loaded changed lines inspectable beside that existing explicit decision.

## Approach and boundaries

Chosen by the implementer: a typed, read-only projection of parsed diff records, 100 records per page, preserving stored order and old/base versus new/head coordinates. Raw patch pagination would lose hunk context across pages; fetching complete files would expand source access. A further historical CLI comparison command is real but less directly useful here. No new network calls, automatic classifications, citations, decisions, gates, storage versions or exports.

`build_scope_file_preview(state, snapshot, path, *, page_index=0)` revalidates state and snapshot, confirmed active criteria/provenance, repository/PR/base/head, visibility, exact unique inventory, ingestion limitations and CI observations. Matching partial source may expose a complete eligible file without relaxing its existing gate. Unknown inventory or conflicting source raises ValueError. The UI also honors the existing source-authority guard. Reopened records without source remain unavailable; existing matching-source attachment policy is unchanged.

The selected path must be canonical and present exactly once. Metadata and explicit unavailable states remain visible for skipped, truncated, unsupported-status, ambiguous-coordinate or empty files, with no content exposed for skipped/truncated files. Inspectable statuses are added, modified, changed, renamed, copied and removed. Removed records use stored old/base coordinates; added/context records use new/head coordinates. Rename origin is shown, without guessing absent origin. No links or full-file equality/completeness claims are added. Duplicate coordinates on either side and malformed multi-record contents fail closed. Separator/control characters are displayed as escapes; tabs remain tabs. Records over 4,096 UTF-8 bytes become explicit omission markers, never truncated excerpts. No sensitive/generated scanning is invented: actual ingestion exclusions remain authoritative.

`ScopeFilePreview` is frozen, extra-forbid, revalidated, and contains owning review/repository/PR/base/head, selected path/status/previous_path, page_index, total_line_count, lines (at most 100), and availability (`available`, `skipped`, `truncated`, `unsupported_status`, `ambiguous_coordinates`, `no_lines`). Lines retain change_type, line_number (or unknown), and content (or an explicit oversized omission); page_count is derived. Nonavailable results contain no lines. Projection and render never mutate source/state or count as runtime evidence or a scope decision.

The workbench places inspection after the selected uncited-file chooser and before disposition controls. It shows inert path/source identity, bounded page selection and labeled base/head coordinates. Missing/mismatched source gives actionable unavailable text, without disabling legitimate explicit decisions or inferring acceptance. Selecting another file clears disposition, criterion, note and page. Review/source-context changes clear the whole target draft, preventing stale retargeting. Rendering uses text/code, never raw source Markdown/HTML.

## Automated completion

Constructed core cases cover add/modify/delete/rename, old/new numbering and gaps, paging and long lines, unknown/duplicate coordinates, missing/truncated/skipped source, matching partial ingestion, inventory/identity/CI conflicts, and unchanged records/gates. AppTest covers inspection before controls and file/context draft reset. Extend an existing installed-browser journey with source preview/draft reset and desktop/phone/CSS-200 captures, without calling simulated actors genuine users. Full suite retains 95% unrounded coverage, lint, lock, deterministic benchmarks, clean wheel/browser, Python and bounded Windows verification. Fresh independent agent review precedes guarded exact-head merge and resulting-main verification.
